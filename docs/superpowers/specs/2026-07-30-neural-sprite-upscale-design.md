# Neural Sprite Upscale (Real-ESRGAN) — дизайн

**Дата:** 2026-07-30
**Статус:** ❌ Gate 0 FAIL — Real-ESRGAN и последующий MMPX-кандидат
отклонены 2026-07-30. Runtime должен остаться на принятом
Super-xBR 4× + Sharpen; незакоммиченный MMPX-прототип не является
визуальным успехом.
**Предыдущий этап:** Enhanced Texture Quality ✅ 2026-07-24 (visual gate:
успех) + Enhanced Warm Performance ✅ 2026-07-24 (warm ~14 с compute /
~2.8–3.7 с cold disk).
**Контекст:** пользовательские отзывы по закрытому texquality-стеку:
    мир (стены/коридоры) в Enhanced стал заметно лучше, но **спрайты —
оружие, монстры, предметы — воспринимаются как «смазанные, а не
качественные»**, при том что именно они первыми бросаются в глаза.
Причина архитектурно известна: типичный кадр спрайта — 30–60 px;
Super-xBR — интерполятор и не синтезирует деталей, а `SharpenFilter 0.5`
возвращает резкость краёв, но не детализацию. Слои, которые «продали»
мир (texel-AA, multi-scale normals, POM), к спрайтам не применяются
сознательно.

## Follow-up Gate 0: MMPX 4× (2026-07-30)

После отклонения Real-ESRGAN был проверен style-preserving кандидат
MMPX: один нормативный проход MMPX 2× и nearest 2× до прежнего
runtime-размера 4×. Для сравнения были взяты четыре WAD-патча:

- монстр `SARGA1`;
- аптечка `MEDIA0`;
- человек-зомби `POSSA1`;
- weapon view `SHTGA0`.

Сравнение выполнялось в одинаковом экранном масштабе: Classic nearest
слева, Enhanced MMPX 4× справа. Локальные PNG находятся в
`Logs/mmpx-classic-enhanced/`.

Доля изменённых пикселей всего изображения составила:

- `SARGA1`: 1,25%;
- `MEDIA0`: 0,43%;
- `POSSA1`: 0,59%;
- `SHTGA0`: 1,98%.

Средняя абсолютная разница канала во всех случаях меньше `0,4 / 255`.
Изменения ограничены отдельными диагоналями и углами; новых деталей
MMPX не создаёт. Интерактивный вердикт: Classic и MMPX воспринимаются
практически одинаково.

**Вердикт: ❌ MMPX Gate 0 FAIL.** Алгоритм не даёт заметного повышения
качества спрайтов Freedoom и не должен заменять принятый
Super-xBR 4× + Sharpen. Незакоммиченная MMPX-интеграция требует
отдельного решения об откате; автоматическая корректность не меняет
визуального результата.

## Цель

Заменить в Enhanced mode алгоритм апскейла **спрайтов, weapon view и
HUD** с Super-xBR 4× + Sharpen на нейронный single-image
super-resolution **Real-ESRGAN 4×** (BSD-3-Clause), исполняемый через
**Unity Sentis** (ONNX):

- монстры, предметы, снаряды, viewmodel оружия и статус-бар получают
  реконструированную детализацию, а не сглаженную интерполяцию;
- мир (world albedo/normals/POM) **не меняется** — он принят
  интерактивно и остаётся на Super-xBR-стеке;
- все инварианты texquality/warm-perf сохраняются: никаких replacement
  assets из авторского контента (вход — только WAD-пиксели), Classic
  не меняется, hot-switch без reload, per-item fallback, session store
  + дисковый pack-кэш.

Важное отличие от FSR/DLSS: те апскейлят **кадр** (рендер в низком
разрешении → нативное). У нас кадр уже нативный; низкое разрешение — у
**текстуры спрайта**. Поэтому решение — texture-space super-resolution
(семейство ESRGAN), а не frame upscaler.

## Почему это может дать «вау», где Super-xBR не дал

- Super-xBR принципиально ограничен интерполяцией имеющихся texels;
  на 30–60-пиксельном «иконочном» арте это мыло + резкие края.
- ESRGAN-семейство обучено синтезировать правдоподобную высокочастотную
  структуру (грани, металл, ткань) — ровно то, чего не хватает вблизи.
- Стоимость инференса амортизируется уже построенной инфраструктурой:
  session store переживает переходы уровней, дисковый pack-кэш делает
  инференс **разовым** на машину/WAD/версию пайплайна.

Это эксперимент: модель может «дорисовать» артефакты, сменить стиль на
«анимешный» или дать мерцание между кадрами анимации. Поэтому:

1. **Gate 0 (до интеграции):** offline-превью на представительных
   спрайтах — если глазами хуже/не лучше Super-xBR, эксперимент
   останавливается без изменения runtime.
2. **Финальный visual gate:** как в texquality — интерактивный eyeball
   с A/B captures; автоматизация зелёная ≠ успех.

## Объём доработки

### 1. Модель и зависимость

- Пакет `com.unity.sentis` добавляется в `Packages/manifest.json`
  (официальный Unity-пакет, лицензия Unity Companion License —
  совместимо).
- Кандидаты модели (выбор — исследовательская задача Gate 0):
  - `RealESRGAN_x4plus_anime_6B` (~18 МБ) — компактная, заточена под
    плоский рисованный арт; основной кандидат;
  - `realesr-animevideov3` (~5 МБ) — быстрая, мягче;
  - `RealESRGAN_x4plus` (~67 МБ) — общая, тяжёлая; запасной вариант.
- Модель вендорится как ONNX в `Assets/ThirdParty/RealEsrgan/` с
  файлом лицензии (BSD-3-Clause) и атрибуцией в third-party notices.
  Конвертация `.pth → .onnx` (при необходимости) выполняется офлайн
  разработчиком; в репозиторий попадает только готовый ONNX-артефакт.
- **Content rule не нарушается:** веса модели — параметры алгоритма
  (как код Super-xBR), а не authored-контент игры. На входе инференса —
  только пиксели, декодированные из WAD; никакие готовые
  изображения-замены в проект не попадают.

### 2. Пайплайн спрайта/HUD в Enhanced

```text
DecodedImage (native, из WAD)
  -> AlphaBleedGuard.Dilate            (RGB в прозрачные texels — как сейчас)
  -> ветка A (RGB):  Sentis Real-ESRGAN 4x  -> RGB
  -> ветка B (alpha): SuperXbr 2x -> 2x     -> alpha (существующий код)
  -> merge: RGB(A из ветки B)
  -> Texture2D (EnhancedNeural4X)
```

- **Alpha не проходит через нейросеть.** Real-ESRGAN — RGB-модель;
  alpha апскейлится существующим детерминированным Super-xBR-путём
  (Clamp wrap), затем каналы сливаются. Cutout shader продолжает
  пороговать alpha; bleed guard до инференса предотвращает тёмные
  halo на границе прозрачности.
- `SharpenFilter` в нейронной ветке **не применяется** (он был
  компенсацией мыла Super-xBR; ESRGAN сам даёт резкий выход). Если
  Gate 0 покажет обратное — включение sharpen фиксируется как решение
  ревизии.
- Нормализация входа/выхода: RGB → float [0,1] → инференс → clamp →
  RGBA32. Выход модели ровно 4× по каждой оси (как текущий вариант —
  placement rects из `PatchHeader` не меняются по построению).
- Дедизеринг: как сейчас для спрайтов (по профилю; на Freedoom ≈ no-op).
- Spectre: материал-флаг, источник тот же — вариант следует профилю
  без изменений.
- Weapon view и HUD (`HudTextureCache`) — тот же пайплайн. Меню и
  intermission остаются native (вне объёма, как в texquality).

### 3. Исполнение и прогрев (интеграция с warm-perf)

Sentis — Unity API: инференс **не может** выполняться в чистом
`EnhancedJobRunner` на worker-потоках. Дизайн:

- **`NeuralUpscaler` (`Doom.MapBuild.Rendering`)** — владелец
  Sentis `Model`/`Worker`; API «RGBA вход → 4× RGB выход», исполнение
  на GPU (`BackendType.GPUCompute`), при отсутствии compute-поддержки —
  CPU backend (Burst). Инстанс один, переживает сцену.
- **`EnhancedWarmScheduler` получает нейронную полосу (main-thread
  lane):** для Sprite/Hud jobs при активных neural-флагах ветка A
  выполняется через `NeuralUpscaler` с бюджетом на кадр (инференс
  мелких изображений — миллисекунды; несколько штук за кадр под
  существующей загрузочной плашкой); ветка B (alpha) остаётся в
  worker-пуле. Merge и `Integrate` — главный поток, как сейчас.
- Порядок разрешения не меняется: **store → disk → compute**; нейронный
  результат публикуется в store и pack-файл как обычный
  `EnhancedJobResult.Rgba`. После первого полного прогрева инференс
  больше не выполняется (диск отдаёт готовые байты).
- **Ленивый путь** (дроп/снаряд, впервые запрошенный в геймплее):
  одиночный инференс допускается синхронно/асинхронно с подменой
  текстуры после готовности (биллборд уже умеет перетаргетироваться
  после интеграции — механика warm-perf Task 5). До готовности — native.
- **Fallback chain per item:** ошибка Sentis (загрузка модели, инференс,
  readback) → существующий Super-xBR+Sharpen путь → native. Отказ
  модели целиком (файл повреждён, backend недоступен) деградирует
  только нейронный слой — Enhanced остаётся Enhanced.

### 4. Presentation contracts

- `GraphicsProfile` получает флаги `SpritesNeural4X`, `UiNeural4X`
  (Classic — false; Enhanced — true при доступной модели). Существующие
  `SpritesUpscale4X`/`UiUpscale4X` остаются как «алгоритмический» слой
  ниже (fallback). Новые user-facing настройки **не добавляются**.
- `EnhancedLayerConfig` включает новые флаги → ключи session/disk кэша
  различают нейронный и Super-xBR состав автоматически.
- `EnhancedPipelineVersion` **инкрементируется** (нейронная ветка меняет
  выходные байты Sprite/Hud kinds; правило версии распространяется на
  выбор модели: смена ONNX-файла = смена версии пайплайна).
- Hot-switch/rollback/exact Classic restore — без изменений.

### 5. Детерминизм — сознательное ослабление для нейро-ветки

GPU-инференс не гарантирует побайтную воспроизводимость между
запусками/драйверами/GPU. Политика:

- дисковый/сессионный кэш замораживает результат на машине — картинка
  стабильна в рамках установки; межмашинная побайтная идентичность
  **не обещается** (кэш per-user, это допустимо);
- существующий тест детерминизма (parallel == sequential) продолжает
  покрывать CPU-ветки (мир, alpha, fallback); нейронная ветка
  покрывается инвариантами (dimensions 4×, alpha из ветки B побайтно,
  повторный инференс в одной сессии стабилен) вместо golden-байтов.

## Сознательно не входит

- Нейроапскейл **мира** (albedo/normals) — мир принят на Super-xBR;
  отдельное решение после оценки спрайтов.
- Апскейл меню и intermission (native, как раньше).
- Обучение/дообучение модели, собственные датасеты.
- Runtime-инференс каждый кадр (только предвычисление текстур).
- FSR/DLSS/frame upscaling любого рода.
- Пользовательские настройки выбора модели/силы эффекта.
- Изменение placement, UV, геометрии билбордов, gameplay, save schema.
- Сжатие pack-кэша (объём Rgba-записей не меняется против texquality).

## Архитектура

### Новые компоненты

- `Assets/ThirdParty/RealEsrgan/` — ONNX-модель + LICENSE + README
  с происхождением и командой конвертации.
- `NeuralUpscaler` (`Doom.MapBuild.Rendering`) — обёртка Sentis:
  загрузка модели, выбор backend, `TryUpscaleRgb(DecodedImage) →
  float[]/byte[]`, dispose. Единственная точка контакта с Sentis.
- `NeuralSpriteComposer` (pure `Doom.Graphics`) — детерминированные
  части: подготовка входного тензора из RGBA (bleed уже применён),
  merge RGB(нейро) + alpha(Super-xBR), clamp/квантование. Тестируется
  EditMode без Sentis.

### Изменяемые компоненты

- `EnhancedJob`/`EnhancedJobRunner` — Sprite/Hud job получает флаг
  `NeuralRgb`; runner при этом флаге строит **только** alpha-ветку
  (RGB-ветка приходит извне через composer) либо целиком fallback-путь.
  Точная форма split'а — решение реализации, инвариант: runner остаётся
  чистым, Sentis в `Doom.Graphics` не попадает.
- `EnhancedWarmScheduler` — нейронная полоса с кадровым бюджетом,
  синхронизация веток A/B, cancel посреди инференса.
- `SpriteCache`/`HudTextureCache` — `TryCreateJob` помечает нейронные
  jobs по профилю; `Integrate` без изменений семантики; failed state
  различает «нейро упало → Super-xBR» и «всё упало → native».
- `GraphicsProfile`/`EnhancedLayerConfig`/`EnhancedPipelineVersion` —
  флаги и версия (см. выше).

## Ресурсы и производительность

- GPU-память: без изменений против texquality — выход тот же 4× RGBA32
  (нейро меняет содержимое, не размер). Спрайты+HUD ≈ прежние байты.
- Модель: +5–18 МБ в build (выбранный ONNX) + Sentis runtime.
- Compute warm: инференс ~350 sprite + ~85 HUD патчей. Ожидание:
  единицы–десятки мс на мелкий патч на GPU → первый полный прогрев
  **гейт ≤ 30 с** (сейчас ~14 с; нейро добавляет сверху, диск делает
  это разовым). Cold disk start обязан остаться **≤ ~5 с** (формат
  кэша не меняется).
- Замеры на E1M1/E1M7: первый warm, cold disk, переход уровня,
  повторный switch, пик памяти — до/после, в baseline notes.
- Mitigation ladder при провале warm-гейта:
  1. более лёгкая модель (`realesr-animevideov3`);
  2. нейро только для «крупных в кадре» категорий (монстры, оружие,
     HUD), предметы — Super-xBR;
  3. подъём гейта с явной фиксацией решения (диск всё равно делает
     стоимость разовой).

## Тестирование

### Gate 0 (до интеграции, editor-only)

- Меню `Tools > Doom > Dump Neural Sprite Preview`: для фиксированного
  набора (имп, зомби, шотган-гай в 8 ротациях; viewmodel shotgun;
  medikit; STBAR; кадры анимации ходьбы импа подряд) выгрузить PNG-триптихи
  native / Super-xBR+Sharpen / Real-ESRGAN для каждой модели-кандидата.
- Интерактивный вердикт по превью: детализация, сохранение стиля,
  отсутствие «дорисованных» артефактов, согласованность соседних
  кадров анимации. **Нет улучшения → стоп без изменений runtime.**

### EditMode

- `NeuralSpriteComposer`: тензорная подготовка (размеры, нормализация,
  порядок каналов), merge RGB+alpha (alpha побайтно равна Super-xBR
  ветке; RGB из мока), clamp, вход не мутирует, invalid input
  отклоняется.
- Runner: флаг `NeuralRgb` не ломает чистоту (fallback-путь побайтно
  равен текущему Sprite/Hud пайплайну — регрессия golden-снапшотов).
- `EnhancedLayerConfig`: новые флаги участвуют в ключе; старые записи
  кэша не отдаются под нейронным конфигом (mismatch-тест).
- Codec: запись/чтение нейронных Rgba-записей (формат не меняется —
  smoke).

### PlayMode

- Enhanced sprite/HUD material: 4× dimensions при неизменных
  header dims/offsets/mirror; Classic — native; hot-switch
  восстанавливает native-объекты; spectre следует профилю.
- Модель недоступна (симуляция) → Super-xBR fallback без pink/native
  регрессий; один item упал → fallback только для него.
- Session store: повторная загрузка карты — 0 инференсов; переход
  E1M1→E1M2 переиспользует общие лампы.
- Disk: холодный процесс с pack-файлом — 0 инференсов; смена
  `EnhancedPipelineVersion` → пересчёт и перезапись.
- Отмена посреди нейронного прогрева (смена сцены) — без исключений и
  утечек Sentis-ресурсов.
- E1M1–E1M9 smoke в обоих режимах.

### Capture и интерактивно (финальный visual gate)

- A/B на одинаковых позах (E1M1, E1M3, E1M7): Super-xBR-стек vs
  нейронный — монстр в упор/на средней дистанции, оружие в руках,
  предметы, STBAR; анимация ходьбы/атаки на предмет мерцания деталей.
- Проверка «равномерности картинки»: мир (Super-xBR) и объекты (нейро)
  не должны конфликтовать стилистически.
- Windows standalone: времена warm/cold disk, память, размер build.
- Вердикт eyeball фиксируется; без явного «стало значимо лучше»
  доработка не закрывается как успех.

## Критерий готовности

1. Gate 0 пройден: превью подтверждает превосходство выбранной модели
   над Super-xBR+Sharpen на представительном наборе.
2. Спрайты/оружие/HUD в Enhanced используют Real-ESRGAN 4× (RGB) +
   Super-xBR (alpha); placement неизменен; Classic не изменён; меню и
   intermission native.
3. Fallback chain работает: нейро → Super-xBR → native, per item;
   отсутствие модели не ломает Enhanced.
4. Session store и disk cache отдают нейронные результаты; инференс —
   разовая стоимость; `EnhancedPipelineVersion` инкрементирован.
5. Warm-гейты: первый полный прогрев ≤ 30 с (8C/16T), cold disk ≤ ~5 с;
   числа в baseline notes (или применён/задокументирован mitigation).
6. EditMode, PlayMode, E1 smoke, Windows build зелёные; CPU-ветки
   детерминизма зелёные без правок golden.
7. **Финальный visual gate:** интерактивный A/B eyeball подтверждает
   значимое улучшение спрайтов без потери стиля и мерцания анимации.
   Иначе — итог фиксируется как отрицательный результат эксперимента,
   runtime остаётся на Super-xBR-стеке.
