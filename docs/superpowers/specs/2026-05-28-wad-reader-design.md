# Этап 1. WAD-ридер — дизайн

**Дата:** 2026-05-28
**Статус:** выполнено
**План реализации:** `docs/superpowers/plans/2026-05-28-wad-reader.md`

---

## Цель

Прочитать структуру WAD-файла (заголовок + directory) и предоставить API «достать ламп по имени», верифицированный на `Assets/StreamingAssets/wads/freedoom1.wad`. Это фундамент для всех последующих этапов: вся игровая дата (геометрия, текстуры, спрайты, звук) приходит из WAD, поэтому ридер должен быть надёжным и хорошо протестированным.

---

## Контекст

Это первый этап после Stage 0. Stage 0 уже завёл Unity-проект, положил `freedoom1.wad` в `Assets/StreamingAssets/wads/`, инициализировал Git. Никакого C#-кода в `Assets/Scripts/` ещё нет, asmdef'ов тоже нет — этот этап создаёт всё с нуля.

Архитектурные правила проекта (`CLAUDE.md`), значимые для этого этапа:

- BSP-данные оригинала (`NODES`, `SSECTORS`, `SEGS`, `BLOCKMAP`) **не используются** — в Stage 1 мы и не пытаемся их интерпретировать, просто читаем directory как сырые записи.
- Числа в WAD — **little-endian**, читаются через `BinaryReader` (который и так LE по умолчанию в .NET).
- Не портируется C-код оригинала — пишем парсер с нуля по описанию формата.

«Карты» в WAD — это маркер-лампы с именами `ExMy` (`E1M1`...`E4M9`) или `MAPxx` (`MAP01`...`MAP32`) размера 0, за которыми идут лампы геометрии. В Stage 1 нужно лишь **найти маркеры** для распечатки списка карт; парсинг связок лампов карты — задача Stage 2.

## Объём этапа

**Входит:**

- Чтение заголовка WAD: сигнатура (`IWAD`/`PWAD`), число лампов, смещение directory.
- Чтение directory (записи по 16 байт: смещение, размер, имя; декодинг имени с обрезкой `\0`-падинга).
- Поиск лампа по имени (`FindLump`, первое вхождение) и чтение его сырых байтов (`ReadLump` по имени и по индексу).
- Распознавание маркеров карт (`WadMapNames.IsMapMarker`: `ExMy` и `MAPxx`).
- Валидация битых WAD: неизвестная сигнатура, отрицательное число лампов, directory-смещение вне диапазона.
- Editor-инструмент для ручной проверки (`Tools > Doom > Dump freedoom1.wad`).
- Юнит-тесты на синтетическом WAD и интеграционные тесты на `freedoom1.wad`.

**Сознательно отложено / не делается (и почему):**

- **Парсинг конкретных лампов** (`VERTEXES`, `LINEDEFS`, `PLAYPAL` как структуры) — это Stage 2/4. Здесь только сырые байты.
- **Кэширование лампов в памяти** — не нужно, пока нет проблемы; лениво читаем со `Stream` на каждый запрос (28 МБ в память не грузим).
- **Поддержка PWAD как мерджа поверх IWAD** — конструктор примет PWAD, но логика замены одноимённых лампов появится не раньше, чем понадобится (вряд ли раньше Stage 7).
- **Группы лампов между маркерами `F_START`/`F_END`, `S_START`/`S_END`** — относится к флэтам и спрайтам (Stage 4/5).
- **Юникод/нестандартные регистры в именах лампов** — оригинал и Freedoom всегда ASCII upper-case; сравнения чувствительны к регистру.

## Ключевые решения

1. **Чистый C#, без UnityEngine.** Парсер — в собственной asmdef `Doom.Wad` с `noEngineReferences: true`. Это заставляет компилятор ловить любые попытки протянуть Unity-зависимость в парсер и позволяет тестировать его в EditMode без сцены.
2. **Ленивое чтение со `Stream`.** Поток файла открывается один раз; данные лампа читаются по запросу через `BinaryReader` (little-endian). Весь 28-МБ WAD в память не загружается.
3. **Всё в одном `WadFile.cs`.** Намеренно: header, directory entry, парсер и helper определения карт меняются вместе, дробить по технологическим слоям нет смысла.
4. **Линейный `FindLump` с первым вхождением.** Директория маленькая; линейный поиск достаточен. В реальных WAD одинаковые имена встречаются (`F_START`/`F_END`, лампы карт), поэтому контракт — возвращать индекс первого совпадения.
5. **Маркеры карт распознаём отдельно** (`WadMapNames.IsMapMarker`), потому что это лампы нулевого размера-разделители, а не данные.
6. **Editor-дамп как ручная веха.** Меню `Tools > Doom > Dump freedoom1.wad` — единственная часть этапа, видящая `UnityEngine`/`UnityEditor`; даёт визуальный sanity-check, что ридер видит реальный WAD.

## Архитектура

Публичная поверхность: `WadFile.Open(path)` / конструктор `WadFile(Stream, ownsStream)`, свойства `Header` и `Directory`, методы `FindLump(name)`, `ReadLump(name)` / `ReadLump(index)`, плюс `WadMapNames.IsMapMarker(name)`.

```
Doom.Wad (pure C#, noEngineReferences: true)
└── WadFile.cs
    ├── WadHeader   — Signature / NumLumps / DirOffset
    ├── LumpInfo    — Name / Offset / Size
    ├── WadFile     — Open / Header / Directory / FindLump / ReadLump (+ валидация)
    └── WadMapNames — IsMapMarker(name)

Doom.Wad.Editor (Editor-only)
└── WadInspectorMenu — Tools > Doom > Dump freedoom1.wad
```

### Справка: формат WAD

WAD-файл = заголовок (12 байт) + тело данных лампов + directory (`numLumps` × 16 байт).

**Header (12 байт):**

| Смещение | Размер | Поле             | Описание                                |
|----------|--------|------------------|-----------------------------------------|
| 0        | 4      | `identification` | ASCII: `IWAD` или `PWAD`                |
| 4        | 4      | `numlumps`       | int32 LE — число лампов                 |
| 8        | 4      | `infotableofs`   | int32 LE — смещение directory от начала |

**Directory entry (16 байт):**

| Смещение | Размер | Поле      | Описание                                        |
|----------|--------|-----------|-------------------------------------------------|
| 0        | 4      | `filepos` | int32 LE — смещение данных лампа от начала файла |
| 4        | 4      | `size`    | int32 LE — длина данных в байтах                 |
| 8        | 8      | `name`    | ASCII, до 8 символов, `\0`-падинг; ALL CAPS      |

Имена лампов: до 8 байт ASCII, `\0` — терминатор (всё после первого `\0` игнорируется).

## Тестирование

Стратегия: чистый парсер покрывается юнит-тестами на синтетических данных, и дополнительно проверяется на реальном WAD.

- **Юнит-тесты (`Doom.Wad.Tests`):** `SyntheticWadBuilder` строит минимальный валидный WAD в памяти; тесты проверяют чтение заголовка (`IWAD`/`PWAD`, число лампов, смещение), парсинг directory с обрезкой `\0`-падинга, `FindLump`/`ReadLump` (по имени и индексу, первое вхождение для дублей, исключение на отсутствие), и валидацию битых WAD (неизвестная сигнатура, отрицательное число лампов, слишком короткий файл) — всё без `freedoom1.wad`.
- **Интеграционные тесты на `freedoom1.wad`:** это `IWAD`, несколько тысяч лампов, `PLAYPAL` присутствует (размер 14×256×3 = 10752), `E1M1` — маркер размера 0, и лампы после него идут в каноническом порядке (`THINGS`, `LINEDEFS`, `SIDEDEFS`, `VERTEXES`, …, `SECTORS`). Эти ассерты на конкретные размеры/индексы — самый хрупкий, но и самый ценный момент: страховка от тихих регрессий.

Запуск: Test Runner в редакторе или CLI `-runTests -testPlatform EditMode` (без `-quit`; per-тест результаты пишутся в `-testResults` XML). Точное число тестов и пошаговый список Task — в плане реализации.

## Definition of done / результат

1. Из CLI прогон `-runTests -testPlatform EditMode` возвращает exit 0, все тесты pass (включая интеграционные на `freedoom1.wad`).

4. Документы (`docs/doom-unity-remake-plan.md`, `CLAUDE.md`) отражают новое состояние.
