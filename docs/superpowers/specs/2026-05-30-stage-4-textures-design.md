# Этап 4. Палитра и текстуры — дизайн

**Дата:** 2026-05-30
**Статус:** утверждён (brainstorming), готов к написанию плана реализации
**Предыдущие этапы:** 0–3 завершены (WAD-ридер, геометрия блок-аута, игрок+коллизии)

## Цель

Подтянуть оригинальную графику из WAD на уже построенную серую геометрию E1M1.
Видимый результат этапа: уровень (E1M1 и любой `ExMy`) в оригинальных текстурах —
стены, полы, потолки, прозрачные решётки/заборы, тёмные/светлые зоны по яркости
секторов. Ходьба и коллизии из Stage 3 не затрагиваются.

## Объём этапа

**Входит:**
- Палитра `PLAYPAL` (256 цветов).
- Флэты пола/потолка (сырые 64×64 индекса).
- Стеновые текстуры: сборка из патчей по `TEXTURE1`/`TEXTURE2` + `PNAMES`,
  колоночный формат патчей с прозрачностью.
- Корректные UV и pegging (флаги `lower/upper unpegged`, X/Y-смещения сайддефа).
- `middle`-текстуры на двусторонних линиях (решётки/заборы) с alpha-cutout
  прозрачностью.
- Освещённость секторов: яркость `LightLevel` запекается в vertex color меша.

**Сознательно отложено:**
- Анимация флэтов/текстур (NUKAGE, FIREBLU и пр.).
- Полноценное небо (skybox из `SKY1`) — на Этапе 4 потолки `F_SKY1` просто не
  рисуются.
- Затемнение по дистанции (`COLORMAP`).
- ИИ/алгоритмический апскейл текстур (xBRZ / ESRGAN) — отдельная опциональная
  будущая веха. Прим.: апскейл создаёт производный контент и упирается в правило
  проекта «не авторим ассеты»; делать его осмысленно только поверх работающего
  базового пайплайна.

## Ключевые решения (из brainstorming)

1. **Стратегия рендера:** материал на каждую WAD-текстуру/флэт (Texture2D с
   `wrap=Repeat`); геометрия группируется по материалам в подмеши. Тайлинг
   аппаратный — UV выходят за пределы 0..1. Это классический и самый надёжный путь
   для DOOM; прозрачность middle-стен тривиальна. Цена — десятки материалов
   (приемлемо для одной карты).
2. **Архитектура:** новый pure-C# asmdef `Doom.Graphics` (`noEngineReferences`)
   для декодинга; Unity-glue (`Texture2D`/`Material`) — в `Doom.MapBuild`.
   Согласуется с правилом «парсер не зависит от Unity»; декодинг тестируется в
   быстром EditMode.
3. **Формат пикселей:** декодер выдаёт готовый `RGBA32 byte[]`. Индексы прогоняются
   через палитру внутри декодера; прозрачные пиксели патча → `alpha=0`. Glue
   тривиален (`tex.LoadRawTextureData`). Тот же формат переиспользуется для
   спрайтов (Этап 5).
4. **Шейдер/свет:** Unlit-шейдер (Built-in pipeline), `albedo × vertexColor`, без
   сценного света. Яркость сектора `LightLevel` → vertex color меша. Аутентичный
   DOOM-вид, ламп не нужно.
5. **Небо:** отложено — потолки с флэтом `F_SKY1` не генерируются (в проёме виден
   фоновый цвет камеры).
6. **Фильтрация:** `FilterMode.Point` + mipmaps **on** + anisotropic filtering.
   Чёткие ретро-пиксели вблизи, без мерцания и мути вдали; контент не добавляется,
   правила проекта не нарушаются.

## Архитектура

### Новая сборка `Doom.Graphics` (pure C#, `noEngineReferences: true`)

Зависит только от `Doom.Wad`. Не ссылается на `UnityEngine`. Единый выходной тип:

```
DecodedImage { int Width; int Height; byte[] Rgba; }   // Rgba.Length == Width*Height*4
```

Классы:

- **`Palette`** — читает `PLAYPAL`, отдаёт 256 RGB-цветов (используем палитру 0).
- **`Flat`** — декодит флэт 64×64 (сырые индексы) → `DecodedImage` через палитру.
  Флэты лежат между маркерами `F_START`/`F_END` (учесть варианты `FF_START` и
  под-маркеры `F1_START`/`F2_START` при наличии).
- **`Patch`** — декодит DOOM picture format: заголовок (width, height, leftoffset,
  topoffset) + таблица смещений колонок; каждая колонка — последовательность постов
  (`topdelta`, `length`, пиксели), промежутки между постами прозрачны → `alpha=0`.
- **`PatchNames`** — читает `PNAMES` (список имён патчей; индекс → имя).
- **`TextureSet`** — читает `TEXTURE1` (и `TEXTURE2`, если есть) + `PNAMES`,
  собирает каждую именованную текстуру из патчей в `DecodedImage`; отдаёт размеры
  текстуры по имени (нужно билдерам геометрии для UV). Композиция: пустой холст
  W×H, патчи накладываются по (originX, originY); непрозрачные пиксели патча
  перетирают холст. Дублирующиеся имена текстур: позже определённая побеждает
  (как в оригинале).

Граничные случаи: пустые/`-`/отсутствующие имена текстур (нет текстуры на этой
части стены — геометрия для неё не эмитится); неизвестное имя текстуры/флэта
(лог-предупреждение + видимый плейсхолдер, чтобы не падать на чужих WAD).

### Расширение `Doom.Map`

`Doom.Map` уже `noEngineReferences` и уже ссылается на `Doom.Wad`. Добавляем
ссылку на `Doom.Graphics` (оба pure C# — это законно), чтобы билдеры геометрии
знали размеры текстур для расчёта UV.

- **`MeshData`** дополняется параллельными массивами:
  - `Float2[] Uv` — текстурные координаты (1:1 с `Vertices`).
  - `Float3[] Color` (или `byte`-аналог RGB) — vertex color = яркость сектора.
    Существующие `Vertices`/`Triangles` сохраняются.
- **Группировка по материалам.** Внутри сектора:
  - пол / потолок — один флэт на сектор → одна `MeshData` каждый;
  - стены — группируются по имени текстуры → набор `MeshData`, по одной на
    уникальную текстуру. Это меняет форму `SectorMeshes`: вместо одной `Walls`
    нужен список `(textureName, MeshData)`. Аналогично пол/потолок несут имя флэта.
- **UV и pegging (главная новая логика, `WallMeshBuilder`).** Конвенция:
  1 пиксель текстуры = 1 DOOM-юнит.
  - Горизонталь: `u = (dist_along_wall + side.TextureXOffset) / texWidth`, где
    `dist_along_wall` — расстояние вершины от начала линии в DOOM-юнитах.
  - Вертикаль зависит от типа части и флагов линии (`LINEDEF.Flags`):
    - бит `0x0008` **Lower unpegged**, бит `0x0010` **Upper unpegged**.
    - one-sided (middle): по умолчанию текстура «висит» от потолка вниз;
      Lower unpegged → крепится к полу.
    - upper-перемычка: по умолчанию крепится к низу проёма; Upper unpegged → к
      верху.
    - lower-перемычка: по умолчанию от верхней (большей) высоты; Lower unpegged →
      выравнивание по потолку сектора.
    - `side.TextureYOffset` добавляется к вертикальному сдвигу.
  - UV считаются в DOOM-юнитах **до** умножения позиций на `worldScale` (масштаб
    влияет только на геометрию, не на тайлинг).
- **middle-текстуры двусторонних линий** — новая геометрия (сейчас её нет): один
  квад в вертикальном зазоре, общем для обоих соседних секторов
  (`max(floor)`..`min(ceiling)`), **без вертикального повтора** (как в оригинале —
  middle на two-sided не тайлится по вертикали, обрезается). Помечается на
  alpha-cutout материал.
- **Vertex color.** Для каждого меша (пол/потолок/стена) все вершины получают цвет
  `g = LightLevel/255` (серый). Для стен можно использовать яркость своего сектора
  (упрощение; в оригинале фронт/бэк берут свет своих секторов — для перемычек берём
  сектор-владелец стороны).
- **F_SKY1.** Потолок сектора с флэтом `F_SKY1` не триангулируется (геометрия не
  эмитится).

### Unity-glue в `Doom.MapBuild`

- **`TextureCache`** — `DecodedImage` → `Texture2D`
  (`new Texture2D(w,h,RGBA32,mipChain:true)`, `LoadRawTextureData`, `Apply`;
  `filterMode = Point`, `anisoLevel` высокий, `wrapMode = Repeat`). Кэш по имени.
  Имя текстуры/флэта → `Material` (тоже кэш): opaque-вариант для стен/полов/потолков,
  cutout-вариант для middle.
- **Unlit-шейдер** (Built-in): `albedo(sample) × vertexColor`. Два варианта/режима:
  opaque и alpha-cutout (для middle). Лежит в `Assets/Shaders/` (или `.shader` рядом
  с материалами). Это код шейдера, не «авторский ассет» — правило о контенте про
  текстуры/меши/карты.
- **`MapLoader`** обновляется:
  - читает палитру/`TextureSet` один раз на загрузку карты и передаёт в билдеры;
  - `AddChild` пишет в `Mesh` `uv` и `colors32`, ставит материал из `TextureCache`
    по имени текстуры/флэта;
  - стены: по одному дочернему объекту на текстурную группу (или один меш с
    submesh-ами + массив материалов);
  - коллайдеры без изменений: пол — `Render`, стены — `ThickWall`, потолок — `None`.

### Поток данных

```
WadFile ─► Doom.Graphics: Palette / Flat / Patch / PatchNames / TextureSet
                                   │
                                   ▼  DecodedImage (RGBA32) + размеры текстур
MapData ─► MapGeometryBuilder (UV + pegging + vertex light, группы по текстуре)
                                   │
                                   ▼  MeshData[] (Vertices, Triangles, Uv, Color) + имена
        Doom.MapBuild: TextureCache → Texture2D/Material; Mesh(uv,colors) ─► сцена
```

## Тестирование

**EditMode `Doom.Graphics.Tests`** (синтетические блобы через builder, как в
Stage 1/2):
- `PLAYPAL` парсится в 256 цветов; цвет N совпадает с байтами.
- Флэт 64×64 → `DecodedImage` 64×64×4; пиксель совпадает с палитрой по индексу.
- Патч с прозрачным постом: пиксели вне постов имеют `alpha=0`, внутри — цвет
  палитры; размеры из заголовка.
- `TextureSet`: текстура из 2 патчей собирается в заявленный W×H; патч кладётся в
  (originX, originY); перекрытие — позже определённый патч сверху.
- Интеграция на `freedoom1.wad`: известная текстура/флэт декодятся, проверяем
  размеры и пару опорных пикселей.

**EditMode `Doom.Map`** (синтетика):
- UV стены известной длины/текстуры дают ожидаемые координаты.
- `lower unpegged` vs дефолт дают разный вертикальный сдвиг.
- middle two-sided эмитит квад в зазоре `max(floor)..min(ceiling)`, без повтора.
- потолок `F_SKY1` не порождает геометрию.
- vertex color сектора = `LightLevel/255`.

**PlayMode / визуально:**
- E1M1 грузится без ошибок; smoke-проверка, что материалы/текстуры назначены
  (счётчик подмешей/материалов > 0). Ручная визуальная проверка вида.

## Принятые ограничения / риски

- Десятки материалов на карту — ок для одной карты; батчинг — забота Этапа 7.
- middle-текстуры на two-sided без вертикального повтора — соответствует оригиналу;
  редкие карты с тайлингом middle выглядят иначе (приемлемо).
- Свет стены берётся от сектора-владельца стороны (упрощение относительно оригинала).
- Неизвестные/битые лампы текстур → плейсхолдер + предупреждение, не падение.
