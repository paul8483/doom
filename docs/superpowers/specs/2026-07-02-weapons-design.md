# Этап 6c. Оружие и стрельба — дизайн

**Дата:** 2026-07-02
**Статус:** утверждён (brainstorming), готов к написанию плана реализации
**Предыдущие этапы:** 0–5 завершены; под-этапы 6a (двери/секторы) и 6b (урон/HP) завершены
**Контекст:** третий под-этап Stage 6 (игровая логика). Разрез 6a–6f:
двери/секторы → урон/HP → **оружие** → ИИ → предметы → звук.

## Цель

Дать игроку hitscan-оружие DOOM: кулак, пистолет, дробовик, пулемёт. Выстрел —
мгновенный луч из камеры со свободным прицелом (mouselook уже есть, автоаим DOOM
не нужен). Враги получают HP и умирают (замена спрайта на труп), стрельба тратит
патроны, оружие и патроны подбираются с карты. Видимая веха на E1M1: подойти к
ящикам, подобрать дробовик, застрелить троих зомби, увидеть трупы, увидеть
убывающие патроны.

## Объём этапа

**Входит:**
- **Четыре hitscan-оружия:** кулак (слот 1), пистолет (2), дробовик (3),
  пулемёт (4). DOOM-урон, скорострельность в тиках (35 т/с), разброс.
- **Боезапас:** типы Bullets/Shells, максимумы 200/50, старт — кулак + пистолет
  с 50 пулями. Авто-переключение вниз при пустом боезапасе, авто-переключение
  на новое оружие при подборе.
- **Враги умирают:** HP из mobjinfo (POSS 20, SPOS 30, TROO 60, …); при нуле —
  спрайт заменяется финальным кадром death-последовательности (без анимации),
  коллайдер выключается, труп не простреливается и не блокирует.
- **Узкий срез подбора** (только оружейные вещи, полноценные предметы — 6e):
  шотган (doomednum 2001, +8 дроби), чейнган (2002, +20 пуль), обойма (2007,
  +10), коробка патронов (2048, +50), дробь (2008, +4), коробка дроби (2049,
  +20). Билборд исчезает при подборе.
- **Viewmodel:** спрайт оружия внизу экрана, кадры выстрела + вспышка из WAD
  (PISG/PISF, SHTG/SHTF, CHGG/CHGF, PUNG), DOOM-bob при ходьбе.
- **Эффекты попаданий:** короткоживущие билборды PUFF (стены/пол) и BLUD
  (враги) с автоудалением.
- **Показ патронов:** строка `AMMO` в debug-OnGUI (`PlayerHud`).

**Сознательно отложено:**
- **Ракетница, плазма, BFG, бензопила** — снаряды, сплэш-урон ракет, отдельный этап.
- **Pain-стейты, анимация смерти, звуки, инфайтинг** — 6d (ИИ) и 6f (звук).
- **Полноценный HUD** (цифры, лицо) — Этап 7; сейчас debug-текст.
- **Берсерк, рюкзак (удвоение максимумов), сложность** — с предметами (6e).
- **Автоаим по вертикали** — не нужен, у нас свободный mouselook-прицел.

> **Дополнено 2026-07-11:** взрыв бочек (2035) реализован — HP 20, BEXP,
> `RadiusDamageRules` / `BarrelExplosion`, DSBAREXP. См. план 6c known-simplifications.

## Ключевые решения (из brainstorming)

1. **Реакция цели:** HP + смерть с трупом-кадром, без анимаций и ИИ. Milestone
   «выстрел ощущается», объём не раздувается state-машиной (она поднимется в 6d).
2. **Набор оружия:** только hitscan — один механизм (raycast) на все четыре
   ствола; снаряды позже.
3. **Боезапас с подбором:** старт как в DOOM (кулак+пистолет/50), оружие и
   патроны подбираются касанием билборда — узкий срез только оружейных вещей.
4. **Viewmodel живой:** кадры выстрела + вспышка + bob; статичная картинка не
   передаёт стрельбу.
5. **Эффекты:** PUFF/BLUD обязательны — без них непонятно, куда попал дробовик.
6. **Архитектура — вариант A:** чистые правила в `Doom.Game` (рядом с
   `HealthModel`), данные монстров в `Doom.Things`, Unity-глю в `Doom.MapBuild`.
   Отвергнуты: всё в MonoBehaviour (нетестируемо, вразрез с 6a/6b) и полный порт
   state-машины DOOM (правильно в долгую, но блокирует веху — поднимем в 6d).

## Архитектура

### Сборки и их роли

**`Doom.Game` (есть, дополняется; pure-C#, `noEngineReferences`):**
- `AmmoType` — `Bullets`, `Shells`.
- `WeaponId` — `Fist`, `Pistol`, `Shotgun`, `Chaingun`.
- `WeaponDef` + `WeaponTable` — на каждое оружие: слот, тип/расход патронов,
  количество лучей (дробин), разброс, длительность цикла в тиках, дальность
  (2048 юнитов hitscan / 64 юнита кулак), имена спрайтов viewmodel (оружие +
  вспышка) и последовательность кадров выстрела с длительностями в тиках.
  Источник истины — `p_pspr.c`/`info.c` (точные тики фиксируются в плане).
- `AmmoModel` — счётчики по типам, максимумы (200/50), `TryConsume(type, n)`,
  `Add(type, n)` с клампом.
- `WeaponLoadout` — набор имеющегося оружия, текущее, `TrySelect(slot)`,
  `Give(weapon)` (true если новое → авто-переключение), выбор лучшего доступного
  при пустом боезапасе (порядок P_CheckAmmo: чейнган → дробовик → пистолет →
  кулак).
- `HitscanRules` — формулы урона поверх `DoomRandom`:
  пуля/дробина 5×(1d3) (`P_GunShot`), кулак 2×(1d10) (`A_Punch`); дробовик 7
  дробин с горизонтальным разбросом ±5.6°; пистолет: первый выстрел точный,
  очередь — с разбросом (refire, как в DOOM); пулемёт — разброс всегда.
  Выдаёт список (углы, урон) — чистые данные, Unity пускает лучи.
- `DoomRandom` — порт 256-байтового `rndtable` + индекс (`P_Random`).
  Детерминизм для тестов.

**`Doom.Things` (есть, дополняется):**
- `ThingDef` + `Health` (int, 0 = неубиваемо) и `CorpseSprite`/`CorpseFrame`
  (финальный кадр death-последовательности, без ротаций).
- `ThingTable`: заполнить для монстров E1M1/Doom1 (POSS 20/L, SPOS 30/L,
  TROO 60/M, SARG 150/N, …— точные кадры из `info.c` в плане).

**`Doom.MapBuild` (есть, дополняется):**
- `PlayerWeapons : MonoBehaviour` (на игроке) — владеет `AmmoModel`/
  `WeaponLoadout`/`DoomRandom`; ввод: ЛКМ (удержание = автоогонь для пулемёта,
  очередь пистолета), клавиши 1–4; кулдаун в тиках; на выстрел берёт залп из
  `HitscanRules` и пускает `Physics.Raycast` из центра камеры на каждый луч;
  попадание с `EnemyHealth` → `TakeDamage` + BLUD, иначе → PUFF; блокирует
  переключение до конца цикла выстрела.
- `EnemyHealth : MonoBehaviour` — вешается `ThingSpawner`-ом на вещи с
  `Shootable` и `Health > 0`; `TakeDamage(int)` идемпотентен после смерти;
  смерть: материал билборда ← кадр трупа (через `SpriteCache`), у
  `SpriteBillboard` отключается выбор ротаций (у трупа один кадр),
  `CapsuleCollider` выключается.
- `WeaponView : MonoBehaviour` (на камере) — OnGUI-отрисовка спрайта текущего
  оружия внизу центра экрана (Texture2D из `SpriteCache`, масштаб с
  point-фильтром); проигрывает кадры выстрела по сигналу от `PlayerWeapons`;
  вспышка рисуется поверх; bob — синусоида от горизонтальной скорости
  `CharacterController` (формула DOOM: амплитуда от скорости, период ~0.7 с).
- `HitEffectSpawner` — статический помощник: создать билборд PUFF (кадры
  A→B→C→D, ~8 тиков) или BLUD (C→B→A) в точке попадания (чуть от стены к
  камере), автоудаление по концу последовательности.
- `ThingPickup : MonoBehaviour` — вешается `ThingSpawner`-ом на шесть оружейных
  doomednum'ов; sphere-trigger радиуса подбора; `OnTriggerEnter` с игроком →
  `PlayerWeapons.Pickup(вещь)` → уничтожить GO вещи.
- `PlayerHud` — добавить строку `AMMO {n}` (тип текущего оружия; для кулака —
  прочерк).
- `MapLoader.SpawnPlayer` — навесить `PlayerWeapons` + `WeaponView`, связать с
  `PlayerHud`; `PlayerDeathHandler` при респавне сбрасывает арсенал к старту
  (кулак+пистолет/50). Убитые враги при респавне НЕ восстанавливаются.

## Поток данных

```
ЛКМ → PlayerWeapons:
  кулдаун истёк? оружие не в анимации переключения?
  AmmoModel.TryConsume(def.AmmoType, def.AmmoPerShot)
     нет патронов → WeaponLoadout.SelectBestAvailable() (вниз до кулака), выход
  HitscanRules.FireVolley(def, refire) → [(yawOffset, damage), ...]
  на каждый луч: Physics.Raycast(камера, повёрнутый forward, дальность def)
     hit EnemyHealth → TakeDamage(damage) + HitEffectSpawner.Blood(hit)
        → HP ≤ 0: спрайт ← труп, коллайдер OFF (идемпотентно)
     hit стена/пол   → HitEffectSpawner.Puff(hit)
     мимо (небо/решётка без коллайдера) → ничего
  WeaponView.PlayFireSequence(def)

Клавиши 1–4 → WeaponLoadout.TrySelect(slot) (есть оружие? не стреляем сейчас?)

OnTriggerEnter(ThingPickup) → PlayerWeapons.Pickup:
  оружие: Loadout.Give + Ammo.Add(стартовый боезапас) + авто-select если новое
  патроны: Ammo.Add(количество)
  Destroy(GO вещи)
```

## Детали реализации

- **Тики:** внутренние кулдауны и кадры — в тиках DOOM (35/с), конвертация в
  секунды в одном месте (`WeaponDef`). Точные длительности циклов
  (пистолет/дробовик/пулемёт/кулак) переносятся из state-таблиц `p_pspr.c` на
  этапе плана.
- **Разброс:** горизонтальный, в духе `P_GunShot`: смещение угла
  `(P_Random()-P_Random())` с амплитудой ±5.6°. Вертикальный разброс не
  моделируем (в DOOM его нет у hitscan).
- **Дальности:** `MISSILERANGE` = 2048 DOOM-юнитов (64 м) для огнестрела,
  `MELEERANGE` = 64 юнита (2 м) для кулака.
- **Слои/коллайдеры:** лучи бьют по стенам (thick-коллайдеры), полам и капсулам
  врагов; masked-стены и потолки коллайдеров не имеют — простреливаются, что
  соответствует DOOM (двусторонние решётки не блокируют hitscan, по небу puff
  не рисуется). Капсулу самого игрока исключить (луч из камеры внутри капсулы —
  QueryTriggerInteraction + начальная точка чуть впереди).
- **Труп:** один кадр, без ротаций; `SpriteBillboard` остаётся (труп по-прежнему
  повёрнут к камере), но выбор из 8 ротаций отключается.
- **Viewmodel-спрайты:** лампы PISGA0 и т.п. лежат в спрайтовом неймспейсе —
  каталогизируются существующим `SpriteSet`; offsets патча учитываются при
  позиционировании на экране (WEAPONTOP-семантика — в плане).
- **Респавн (R):** `HealthModel.Reset()` (6b) + сброс `AmmoModel`/`WeaponLoadout`
  к старту. Трупы и подобранные вещи остаются как есть.

## Краевые решения

- **Пустой боезапас** → авто-переключение вниз (чейнган → дробовик → пистолет →
  кулак); «сухого щелчка» нет.
- **Переключение во время выстрела** — запрещено до конца кадровой
  последовательности.
- **Выбор слота без оружия/уже текущего** — no-op.
- **Двойное убийство за залп** (несколько дробин) — `TakeDamage` после смерти
  игнорируется.
- **Подбор при полном боезапасе** — чисто патронная вещь остаётся лежать (как в
  DOOM: полную обойму не подобрать). Оружейная вещь: если оружия ещё нет —
  подбирается всегда (даже с полными патронами); если оружие уже есть и патроны
  полные — остаётся лежать.
- **Труп на лифте** — без коллайдера не едет; принимаем (в DOOM трупы тоже
  утапливаются движущимися секторами).

## Тестирование

- **EditMode `Doom.Game.Tests`:**
  - `DoomRandom`: первые N значений совпадают с rndtable; детерминизм от seed.
  - `HitscanRules`: урон пули ∈ {5,10,15}; кулак ∈ {2..20, чётный}; дробовик
    даёт ровно 7 дробин, разброс в пределах ±5.6°, у пистолета первый выстрел
    без разброса.
  - `AmmoModel`: клампы к максимумам, `TryConsume` при нехватке — false.
  - `WeaponLoadout`: старт кулак+пистолет; `Give` нового → true (переключение);
    авто-даунгрейд по порядку P_CheckAmmo; `TrySelect` без оружия — false.
  - `WeaponTable`: у всех четырёх — валидные слоты, спрайты, тики > 0.
- **EditMode `Doom.Things.Tests`:**
  - У каждого `Shootable`+`CountKill` монстра таблицы `Health > 0` и задан кадр
    трупа.
  - Интеграция freedoom1.wad: для каждого монстра E1M1 спрайт кадра трупа
    резолвится в `SpriteSet` (по образцу every-sprite-resolves).
- **PlayMode `WeaponPlayTests` (3 шт.):**
  - Выстрелы пистолета по заспавненному впереди POSS: HP доходит до нуля,
    спрайт сменился (материал ≠ исходный), коллайдер выключен.
  - Стрельба тратит патроны; при нуле — текущее оружие сменилось на кулак.
  - Вход в триггер шотгана: `WeaponLoadout` содержит дробовик, дробь +8,
    GO вещи уничтожен.

## Открытые риски / на проверку при реализации

- **Соответствие Freedoom-спрайтов кадрам DOOM** — кадры трупов (L/M/N…) и
  viewmodel-лампы (PISG/SHTG/CHGG/PUNG + вспышки) проверить регрессией по
  `SpriteSet`; Freedoom обязуется соответствовать неймингу, но проверяем.
- **Raycast из камеры и собственная капсула игрока** — исключить самопопадание
  (маска или стартовое смещение луча).
- **OnGUI-масштабирование viewmodel** — point-фильтр и целочисленный множитель,
  чтобы пиксель-арт не мылился; выверить привязку к низу экрана на разных
  разрешениях.
- **Пулемёт и частота кадров** — кулдоун в тиках через аккумулятор времени (как
  `FloorDamageSystem`), не через кадры.
- **Порядок компонент при смерти врага** — `EnemyHealth` меняет материал у
  `SpriteBillboard`; убедиться, что тот не перезапишет материал в своём
  `LateUpdate` (отключать выбор ротаций флагом, а не гонкой).
